# Тикет P10 — кнопка «Снять дату выдачи» на складе

## Контекст

P9 внедрён: стирки на склад создаются без даты выдачи и показываются нейтральной карточкой «На складе». Назначить дату владелец может («Изменить дату» → `updateIssueDate` → автосоздание визита через `ensureVisit_`). А вот **снять** назначенную дату легально нельзя — только SQL в контейнере, как мы делали на production с wash_115/116/118/121/125.

Сейчас `updateIssueDate('')` ещё и опасен: `ensureVisit_` вызывается безусловно и создаст визит развоза **с пустой датой**. Нужна кнопка и серверная поддержка.

## Часть 1 — сервер: `updateIssueDate` принимает пустую дату

`server/wash.js`, функция `updateIssueDate`. Текущее тело:

```js
const old = found.obj.issue_date;
found.obj.issue_date = issueDate;
db.updateRow_(SHEETS.WASHES, found.rowNumber, found.obj);
logEvent(actorOf_(session), 'wash_edit', washId, { issue_date: old + ' → ' + issueDate }, laundryId);
// Чистое с новой датой выдачи появляется в плане/развозе на этот день
ensureVisit_(found.obj.client_id, issueDate, laundryId, actorOf_(session));
return ok_({ wash: found.obj });
```

Заменить на:

```js
const old = found.obj.issue_date;
if (issueDate === old) return err_('Дата не изменилась');
found.obj.issue_date = issueDate;
db.updateRow_(SHEETS.WASHES, found.rowNumber, found.obj);
logEvent(actorOf_(session), 'wash_edit', washId,
  { issue_date: issueDate ? old + ' → ' + issueDate : old + ' → снята' }, laundryId);
// Визит создаём только при НАЗНАЧЕНИИ даты. Снятие даты визит НЕ отменяет:
// если на старую дату визит уже есть, владелец убирает его на странице «План»
// (cancelDeliveryVisit) — автоотмена могла бы снести чужие планы (в визите
// может быть забор грязного или чистое других стирок).
if (issueDate) ensureVisit_(found.obj.client_id, issueDate, laundryId, actorOf_(session));
return ok_({ wash: found.obj });
```

Три изменения:
1. `issueDate === old` → ошибка-защита от no-op (заодно закрывает повторное нажатие и вызов с `''` у карточки, где даты и так нет).
2. Лог при снятии: `issue_date: '2026-09-08 → снята'` — читается в истории однозначно.
3. `ensureVisit_` — только под `if (issueDate)`. Пустая дата никогда не доходит до Deliveries.

Роль не меняется (`updateIssueDate` уже владельческий метод). Статус стирки не трогаем — `done`/`stored` остаются как есть, карточка просто становится нейтральной «На складе» (логика P9 в `storage-entry.ts` уже это умеет).

## Часть 2 — UI: кнопка в модалке карточки склада

`client/src/app/(dashboard)/storage/storage-card-modal.tsx`, блок `view === 'main' && e.kind === 'clean'`, ряд кнопок «Добавить в развоз» / «Выдано» / «Изменить дату».

Добавить четвёртой (показывать **только когда `e.issue_date` непуста**):

```tsx
{e.issue_date && (
  <Button variant="ghost" className={styles.actionBtn} onClick={() => setConfirmClear(true)}>
    Снять дату выдачи
  </Button>
)}
```

Новый стейт и мутация рядом с существующими:

```tsx
const [confirmClear, setConfirmClear] = useState(false);
const clearIssue = useApiMutation('updateIssueDate', {
  invalidate: 'operational',
  onSuccess: () => { setConfirmClear(false); onClose(); toast('Дата выдачи снята ✓'); },
});
```

И второй `ConfirmDialog` (по образцу `confirmIssue`):

```tsx
<ConfirmDialog
  open={confirmClear}
  onClose={() => setConfirmClear(false)}
  onConfirm={() => clearIssue.mutate([e.id, ''])}
  text={`Снять дату выдачи у «${e.client_name}»? Карточка станет нейтральной «На складе». Если на эту дату уже есть визит в развозе — он останется, удалите его на странице «План».`}
  okLabel="Снять дату"
  busy={clearIssue.isPending}
/>
```

Предупреждение про визит обязательно в тексте — это главный сюрприз, который кнопка должна честно озвучить.

## Часть 3 — UI-мелочь: пустая дата в модалке

В том же блоке clean-карточки строка `Выдача: <b>{e.issue_date}</b>` при пустой дате показывает «Выдача: » с пустотой. Заменить на:

```tsx
<div className={styles.meta}>
  Выдача: <b>{e.issue_date || 'не назначена'}</b>
  {overdueDays > 0 && (/* как сейчас */)}
</div>
```

(`overdueDays` при пустой дате и так 0 — `daysDiff('')` возвращает 0.)

## Тесты

`server/test/` (к существующим наборам по wash):

1. **Снятие даты.** Стирка `done`, `issue_date = 2026-09-10`. `updateIssueDate(id, '')` → ok; в Washes `issue_date === ''`; статус не изменился; **в Deliveries новых строк нет** (главная проверка — регрессия на безусловный `ensureVisit_`); в Log `wash_edit` с `issue_date: '2026-09-10 → снята'`.
2. **No-op.** Стирка `done`, `issue_date = ''`. `updateIssueDate(id, '')` → ошибка «Дата не изменилась», визитов не создано.
3. **Регрессия назначения.** `updateIssueDate(id, '2026-09-12')` по-прежнему создаёт визит на 2026-09-12 (или находит существующий) — поведение до тикета не сломано.
4. **Статусный барьер.** `updateIssueDate` у стирки `planned`/`issued` → та же ошибка «Менять дату выдачи можно только у завершённой стирки», что и раньше (проверка стоит до нового no-op guard — порядок сохранить).

UI тестов не требуется (проект их не пишет); ручная проверка по критериям.

## Критерии приёмки

- [ ] У clean-карточки с датой выдачи в модалке есть кнопка «Снять дату выдачи»; у карточки без даты — нет.
- [ ] По кнопке — ConfirmDialog с предупреждением про остающийся визит; подтверждение снимает дату, карточка на складе становится «На складе» (без красноты).
- [ ] Снятие не создаёт и не отменяет визиты в Deliveries (проверено тестом 1).
- [ ] Назначение даты через «Изменить дату» работает как раньше, визит создаётся (тест 3).
- [ ] В модалке карточки без даты строка читается «Выдача: не назначена».
- [ ] В Log событие `wash_edit` с человекочитаемым `→ снята`.

## Что НЕ входит

- Массовое снятие дат (после выкатки wash_154/155/156 разберёшь этой кнопкой за минуту — SQL больше не нужен).
- Автоотмена визита при снятии даты (осознанное решение: визит — не собственность стирки).
- Кнопка у работника: даты выдачи — зона владельца, работнику достаточно видеть «На складе».

## Оценка

Час-два с тестами. Один коммит: сервер + UI + тесты — части независимы по файлам, но маленькие, разделять незачем.

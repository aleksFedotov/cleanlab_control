# Тикет P6 — правка состояния визита задним числом (владелец и водитель)

**Ветка:** от master
**Оценка:** 1–2 дня
**Файлы:** `server/deliveries.js`, `server/api.js`, `client/src/app/driver/page.tsx`, `client/src/app/(dashboard)/delivery/page.tsx`, `types/api`, тесты `server/test/`

## Проблема

Водитель (или владелец) случайно нажал не то: «Доставлено» вместо «Забрал грязное», «Ничего нет» по ошибке, не тот этаж подъёма. Сейчас визит закрывается (`VISIT_FINAL = delivered | picked | both | empty`), `driverAction` отвечает «Визит уже закрыт» — и исправить нечем. Деньги при этом считаются по этим данным: этаж и факт рейсов идут и в счёт клиенту, и в зарплату водителя.

## Что уже есть (не делаем заново)

- `setVisitLiftFloor(token, visitId, floor)` — правка этажа задним числом, **owner-only**. Счёт пересчитывается сам (строится по текущему `lift_floor`).
- Зарплата (P3) и счета (P2) вычисляются «вживую» по текущим полям визита — **любая правка автоматически исправляет начисления за период**, отдельный пересчёт не нужен (до появления снапшотов счетов — это плюс).
- `driverAction` разрешён ролям `['driver','owner']` — владелец может отмечать действия тем же механизмом.

## Что правим и что нет

**В scope:**
1. Этаж подъёма — редактируют обе роли (расширить `setVisitLiftFloor` на driver).
2. Отмена ошибочных действий водителя (undo) — 4 операции, ниже.
3. После отмены — сразу отметить правильное действие тем же `driverAction` (визит снова `planned`).

**Вне scope:** перенос даты закрытого визита, удаление закрытого визита, отмена сдачи грязного на склад (`dirty_handed_at`) — если грязное ушло на склад, его могли уже постирать; это ручной разбор через склад, в тикет не входит (сервер отказывает с понятным сообщением).

## Сервер

### 1. Новый метод `correctVisit(token, visitId, op)`

Роли `['driver','owner']`. Тенант-проверка — существующий `findTenantVisit_`. Операции:

| op | Условие | Что делает | Побочки |
|---|---|---|---|
| `undo_empty` | `status='empty'` | `status='planned'`, `delivered_at=''` | нет |
| `undo_take_clean` | `clean_taken_at` и не `delivered_at` | `clean_taken_at=''`, `clean_bags=''` | Storage: чистые строки клиента с `consumed_at='driver'` → `''` (чистое возвращается на склад) |
| `undo_deliver` | `delivered_at` (status delivered/both) | `delivered_at=''`; `status = picked_at ? 'picked' : 'planned'` | Washes с `issued_at === delivered_at` → `status='stored'`, `issued_at=''`; их складские строки (по `wash_id`, kind=clean) → `consumed_at='driver'` (чистое снова у водителя) |
| `undo_pickup` | `picked_at`; **блок: `dirty_handed_at` ≠ пусто** → ошибка «Грязное уже сдано на склад — правьте через склад» | `picked_at=''`, `pickup=''`; `status = delivered_at ? 'delivered' : 'planned'` | нет (склад pickup не трогает) |

Детали:
- Порядок отката составного визита (`both`): сначала `undo_deliver`, потом `undo_pickup` (или наоборот — обе операции независимы, сервер не навязывает порядок, но UI показывает обе кнопки).
- Если при `undo_deliver` стирки с `issued_at === delivered_at` не нашлись (уже правили вручную) — визитные поля всё равно откатываем, в Log пишем `warn: washes_not_found`.
- Лог: событие `visit_correct` с `{ op, before: { status, delivered_at, picked_at, clean_taken_at, lift_floor }, after: {...} }` — как было/как стало, actor из сессии.
- Нет привязки визита к конкретному водителю (поля нет) → поправить может любой водитель прачки; это осознанно, виновник виден в Log. Ограничение «только последние N дней» не вводим — «История» и так ходит по любым датам.

### 2. `setVisitLiftFloor` — права `['owner','driver']`

Больше ничего в методе не меняем. `normalizeLiftFloor_` (пусто/1/2 → без доплаты) уже общий.

### 3. Регистрация в `api.js`

`correctVisit` в реестр методов; контракт как везде: `POST /api/correctVisit`, `{args:[visitId, op]}`. Тип `DecoratedVisit`/визит маршрута в `types/api` не меняется (поля те же).

## Клиент — экран водителя (`driver/page.tsx`)

Вкладка **«История»**:
1. Карточки выполненных визитов становятся кликабельными (`interactive`) → открывается тот же модал точки, что на вкладке «Маршрут» (`visitTarget`), но в режиме закрытого визита:
   - степпер «Этаж» остаётся и **сохраняется сразу** через `setVisitLiftFloor` (кнопка «Сохранить этаж» или по изменению — выбрать по изменению с debounce/кнопкой, на усмотрение; проще — маленькая кнопка «Сохранить» рядом);
   - вместо кнопок действий — блок **«Исправить»**: ghost-кнопки отмен по текущему состоянию (`Отменить выдачу чистого` / `Отменить забор грязного` / `Отменить «Ничего нет»`, `Отменить «Взял чистое»` для незакрытого визита с `clean_taken_at`);
   - после успешной отмены визит снова `planned` → модал тут же перерисовывается в обычный режим с кнопками действий (`actionsFor`) — водитель сразу отмечает правильное, не уходя с экрана. (Без этого отменённый визит «прошлой даты» пропал бы из истории в никуда: вкладка «Маршрут» показывает только сегодня.)
2. Подтверждение отмены — `ConfirmDialog` («Отменить выдачу чистого по точке “X”? Счёт и зарплата за период пересчитаются.»).
3. Мутации: `useApiMutation('correctVisit', { invalidate: 'operational' })`, `useApiMutation('setVisitLiftFloor', …)`; тост «Исправлено ✓». Ошибка блока (грязное сдано) прилетает тостом из `useApiMutation` как обычно.

## Клиент — «Развоз» у владельца (`(dashboard)/delivery/page.tsx`)

Сейчас закрытые визиты — просто карточки с бейджем, действий ноль. Делаем симметрично:
1. Карточка любого **закрытого** визита кликабельна → тот же модал правки (этаж + кнопки отмен + после отмены — кнопки действий; `driverAction` владельцу уже разрешён). Общий компонент — вынести `VisitEditModal` (используется и на странице водителя, и здесь), чтобы не разъезжались.
2. Для `planned` визитов поведение не меняется (существующие «отменить»/«убрать»/pickup_only остаются на карточке).
3. Дата страницы — из хедера (`useSectionDate('delivery')`), т.е. владелец и так может открыть любой прошлый день и там править.

## Деньги

Ничего дополнительно не пересчитываем: счёт (`getClientInvoice`), финансы (`getFinanceSummary`), зарплата (`getPayroll`) и статистика дня водителя строятся по текущим полям визита. В тексте подтверждений честно пишем «счёт и зарплата за период пересчитаются».

## Тесты

**Сервер (`server/test/deliveries.test.js` или отдельный `visit-correct.test.js`):**
- `undo_empty`: empty → planned, поля чистые.
- `undo_take_clean`: складские строки `consumed_at='driver'` → `''`, визит без `clean_taken_at`; блок при `delivered_at`.
- `undo_deliver`: стирки issued → stored, складские строки снова `'driver'`, status both→picked / delivered→planned; случай «стирки не найдены» — визит всё равно откатан, warn в деталях лога.
- `undo_pickup`: picked → planned, both → delivered; **блок при `dirty_handed_at`** с текстом ошибки.
- После любой отмены `driverAction` снова работает по этому визиту (правильное действие фиксируется).
- `setVisitLiftFloor` водителем: 5 → '5', 2 → '' (доплаты нет), зарплатный расчёт подъёма меняется.
- Права: worker/client — «Нет доступа» на оба метода; чужой `visitId` (другая прачка) — «Визит не найден».
- Лог: событие `visit_correct` с before/after.

**Клиент (вручную/Playwright):**
- Водитель: история → тап по точке → отменить действие → появились кнопки действий → отметил правильно → точка снова в истории с новым статусом.
- Владелец: развоз вчерашней даты → тап по закрытой точке → поменял этаж → в «Финансах»/счёте сумма подъёма изменилась.

## Критерии приёмки

1. Любое действие водителя по точке можно отменить (в пределах блока про сданное грязное) — и владельцем, и водителем.
2. Этаж подъёма правится обеими ролями за любую дату.
3. После отмены правильное действие отмечается тут же, без ухода с экрана.
4. Счета и зарплата после правок сходятся с новыми данными без каких-либо дополнительных действий.
5. Все правки видны в журнале (кто, что, было/стало).

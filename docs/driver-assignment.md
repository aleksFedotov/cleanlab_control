# Распределение развоза между водителями

В разделе «Развоз» владелец выбирает водителя каждой точки. Фильтр позволяет
посмотреть точки конкретного водителя или неназначенные. Водитель видит только
свои точки, включая историю, и только свой груз. Неназначенные новые точки видны
только владельцу, даже если в прачке один водитель. Назначение относится к визиту
на конкретную дату и не копируется на следующие визиты клиента.

Переназначение и снятие назначения доступны до начала работы. После погрузки
сначала нужно вернуть чистое на склад; другие действия по точке также нужно
отменить. Передача груза между водителями одной сменой назначения не поддерживается.
После полной отмены действий назначение сохраняется, и владелец может его изменить.

## Данные и API

- `Deliveries.assigned_driver_id` (TEXT, схема v13) — плановое назначение.
- `driver_id` — фактический исполнитель для зарплаты и статистики. При отметке
  владельцем назначенной точки исполнителем остаётся назначенный водитель.
- `assignDeliveryDriver(token, visitId, driverId)` — только владелец; пустая строка
  снимает назначение. Допустим только активный водитель той же прачки.
- `getDeliveryVisits` дополнительно возвращает безопасный список `drivers: [{id, name}]`
  и `assigned_driver_name` в визитах. Пароли и прочие данные учёток не возвращаются.
- Маршрут, груз, погрузка, сдача грязного, возврат, исправления и этаж ограничены
  назначенными точками на сервере. Старый известный исполнитель используется,
  если назначения ещё нет. Владелец сохраняет доступ ко всем точкам своей прачки.
- Маршрут и развоз обновляются каждые 15 секунд в открытой вкладке.

## Обновление

Сначала обновить API, затем фронт. SQLite добавляет колонку автоматически,
существующие данные не переписываются. Новый фронт допускает старый ответ API
без списка водителей: элементы назначения в таком случае скрыты.

Старые визиты с известным исполнителем остаются в его истории и грузе.
Если до обновления чистое погрузили без записи исполнителя, владелец должен
указать текущего держателя этой точки. Назначать завершённую точку нельзя.

## Проверка

Серверные сценарии: два водителя одной прачки, чужая прачка, неназначенные точки,
ограничения всех команд, раздельный груз, отмены, переназначение, зарплата,
старая история и повторное открытие старой SQLite-базы.

Браузерные сценарии с настоящим Express: назначение владельцем, фильтр,
два отдельных аккаунта, выполнение своей точки и снятие назначения.
Проверены ширины 1280 и 390 пикселей.
# Массовое назначение

В «Развозе» владелец может выбрать несколько ещё не начатых точек и назначить им активного водителя. «Выбрать все» учитывает текущую дату и оба фильтра. При смене даты или фильтров, успехе либо ошибке назначения выбор сбрасывается. Одиночное назначение сохранено.

Метод владельца `assignDeliveryDrivers(token, visitIds, driverId)` возвращает `{ ok: true, assigned: number }`. Повторные идентификаторы учитываются один раз. Сервер проверяет весь набор внутри транзакции до записи; чужая, отменённая, завершённая или начатая точка отклоняет весь запрос. Массовое снятие назначения не предусмотрено. Аудит сохраняется для каждой точки.

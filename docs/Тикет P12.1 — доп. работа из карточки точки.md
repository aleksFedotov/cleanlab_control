# Тикет P12.1 — точка входа «Доп. работа» в карточке визита

## Контекст

P12 выкачен: у водителя есть секция «Доп. работы» внизу экрана маршрута. Но работа вспоминается на точке — в момент визита или сразу после («пока нёс мешки, клиент попросил…»). Добавляем **вторую точку входа** прямо в карточку визита с предзаполненными клиентом и датой. Нижняя секция **остаётся**: доп. работа бывает у клиента вне сегодняшнего маршрута — там нет карточки.

Сервер не трогаем: `addExtraWork` (P12) уже всё принимает. Тикет чисто клиентский.

## Часть 1 — проп роли в VisitEditModal

`client/src/components/VisitEditModal.tsx` — модал **общий**: маршрут/история водителя и «Развоз» владельца (P6). Кнопку видит **только водитель**.

Сейчас модал роль не знает. Добавить необязательный проп:

```tsx
export interface VisitEditModalProps {
  visit: VisitEditTarget | null;
  onClose: () => void;
  viewerRole?: 'driver' | 'owner'; // кнопка «Доп. работа» — только driver
}
```

Родители проставляют явно: `driver/page.tsx` → `'driver'`, страница «Развоз» владельца → `'owner'` (или не передаёт — пусто = не водитель, безопасный дефолт). Роль по URL страницы не вычислять — модал переиспользуется.

## Часть 2 — кнопка в модале

Расположение — **в самом низу** карточки, после блока «Исправить»/кнопки возврата чистого:

```tsx
{viewerRole === 'driver' && visit.date <= todayStr() && (
  <Button variant="ghost" className={styles.bigBtn} onClick={() => setExtraOpen(true)}>
    ＋ Доп. работа
  </Button>
)}
```

Три условия показа:

1. `viewerRole === 'driver'` — у владельца в развозе кнопки нет (его путь — блок на странице зарплат; владельцу доп. работы в зарплату не начисляются).
2. **Оба режима карточки:** planned (кнопки действий) и закрытый визит (правки) — работа вспоминается и после закрытия точки.
3. `visit.date <= todayStr()` — для будущих дат скрываем: сервер всё равно отклонит (дата не в будущем, P12), не дразним ошибкой.

Не делать равноправной с действиями визита: ghost, визуально вторична — основной поток карточки (этаж + действие) не меняется.

## Часть 3 — переиспользование модалки доп. работы

Модалку из P12 (секция «Доп. работы» в driver/page.tsx) вынести в общий компонент (например, `components/ExtraWorkModal.tsx`) и использовать в обоих местах. Новые необязательные пропсы:

```tsx
export interface ExtraWorkModalProps {
  date: string;              // дата работы
  clientId?: string;         // предзаполненный клиент (из карточки визита)
  lockClient?: boolean;      // select заблокирован — работа привязана к точке
  onClose: () => void;
}
```

Из VisitEditModal вызывается так: `date = visit.date` (**дата визита**, не «сегодня» — водитель листает историю!), `clientId = visit.client_id`, `lockClient = true`. Из нижней секции — как сейчас (дата экрана, клиент выбирается).

После сохранения: тост «Доп. работа добавлена ✓», модалка доп. работы закрывается, **карточка визита остаётся открытой** (водитель может продолжить действия по точке). Invalidate должен накрывать и список доп. работ нижней секции (общий query-ключ), чтобы запись появилась там без перезагрузки.

## Тесты

Серверных нет (API не меняется). Ручная проверка по критериям; при наличии UI-тестов в проекте — smoke на ролевой gate.

## Критерии приёмки

- [ ] В карточке визита у водителя (маршрут и история, оба режима — planned и закрытый) внизу есть ghost-кнопка «＋ Доп. работа».
- [ ] В «Развозе» владельца кнопки нет (модал та же — проверить!).
- [ ] Из карточки модалка открывается с клиентом точки (заблокирован) и датой визита, а не сегодняшней.
- [ ] После сохранения карточка визита не закрывается; запись появляется в нижней секции «Доп. работы» за эту дату.
- [ ] На будущей дате кнопки нет.
- [ ] Нижняя секция «Доп. работы» работает как раньше (клиент выбирается вручную).

## Что НЕ входит

- Изменения сервера и зарплаты (всё уже в P12).
- Список доп. работ внутри карточки визита (только ввод; просмотр — нижняя секция и страница зарплат).
- Привязка записи к visit_id — по-прежнему достаточно client_id (см. P12, «Что НЕ входит»).

## Оценка

1–2 часа: проп + кнопка + вынос модалки в общий компонент. Один коммит.

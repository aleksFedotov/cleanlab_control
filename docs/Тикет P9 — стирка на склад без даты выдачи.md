# Тикет P9 — стирка на склад без даты выдачи

## Контекст

Сейчас любая стирка получает `issue_date` автоматически: внеплановая от
работника (`addUnplannedWash`) — всегда «завтра», автостирка из развоза —
дату визита. Если развоза на эту дату не случилось, карточка на странице
«Склад» краснеет («Просрочено на N дн.») и попадает в «Требует решения»,
хотя никакого обещания выдачи не было — тревога срабатывает на собственное
допущение системы.

В цеху физически два разных режима: «стираем в свободное время на склад»
(запас) и «стираем под конкретный развоз». Система должна их различать:

- **работник** никогда не ставит дату выдачи — его стирки уходят на склад
  готовым запасом без даты;
- **владелец** при добавлении стирки выбирает: «дата выдачи» (как сейчас)
  или «просто постирать» (без даты);
- мост «назначить выдачу позже» уже есть: `updateIssueDate` на done/stored
  ставит дату и создаёт визит развоза (`ensureVisit_`). Остаётся основным
  способом отправить запас клиенту.

Автостирки из плана развоза (`ensureWashesFromDelivery_`) **не меняются** —
у них дата настоящая, просрочка по ним честная.

## Часть 1. Работник: `addUnplannedWash` без даты (server/wash.js)

- Убрать `issue_date: addDaysStr_(today, 1)` → `issue_date: ''`.
- Обновить комментарий: внеплановая стирка = стирка на склад, дату выдачи
  назначает владелец, когда решит отправить.
- UI работника не трогаем: форма и так не спрашивает дат.

## Часть 2. Владелец: `addToDelivery` с необязательной датой (server/api/washes.js)

- `issueDate` становится необязательной: пустая строка = «просто постирать».
- Валидация: если `issueDate` задана — не раньше `washDate`
  (`err_('Дата выдачи раньше даты стирки')`); пустая — допустима.
- UI владельца (форма добавления стирки, вызовы `addToDelivery` — найти по
  клиенту): переключатель «Выдача: дата / Просто постирать». По умолчанию —
  «дата» (текущее поведение), при «просто постирать» поле даты выдачи
  скрывается и уходит `''`.

## Часть 3. `completionStatus_` — явно (server/core.js)

С пустой датой строковое сравнение и так вернёт 'done' — сделать это
намерение явным и зафиксировать:

```js
function completionStatus_(washDate, issueDate) {
  if (!issueDate) return 'done'; // стирка на склад: ждёт решения о выдаче
  return issueDate > addDaysStr_(washDate, 1) ? 'stored' : 'done';
}
```

## Часть 4. `getDeliveryPlan`: страж пустой даты (server/api/washes.js)

Критично: в JS `'' < date` — true, без стража все бессрочные стирки посыпятся
в «просроченную выдачу».

```js
overdueIssue: all.filter(function (w) {
  return w.issue_date && w.issue_date < date &&
    (w.status === 'done' || w.status === 'stored');
})
```

`issueToday` (`issue_date === date`) пустую не матчит — оставить.

## Часть 5. Страница «Склад»: нейтральная карточка без даты (client/.../storage/storage-entry.ts)

Сейчас `daysDiff('')` → 0 → карточка показывает «Выдача сегодня» — враньё.
Отдельная ветка для clean-записей без `issue_date`:

- `statusText = 'На складе'`, `statusKey = 'ready'`, `attn = false`,
  `rank = 3` (рядом с «Готово к выдаче», без красноты);
- `metaOf` уже умеет без даты (`e.issue_date ? ... : ''`) — проверить.

Поведение записей с датой не меняется: «Выдача сегодня» / «Просрочено» /
«Готово к выдаче» — как раньше.

## Что не трогаем

- `ensureWashesFromDelivery_`, `updateIssueDate` + `ensureVisit_`, весь
  развозной контур (`issueForVisit_`, водитель).
- Отчёты, счёт, payroll: всё считается по `wash_date`, дата выдачи на них не
  влияет. `notReadyForDelivery_` работает по визитам — без изменений.
- P7 «Осталось со вчера»: по `wash_date` и статусам — без изменений.

## Тесты (server/test/wash.test.js)

1. `addUnplannedWash` → стирка с `issue_date=''`.
2. `completeWash` по стирке с пустой датой → статус `done` (фиксация
   `completionStatus_` на пустую дату).
3. `addToDelivery` с `issueDate=''` → стирка с пустой датой; с датой раньше
   `washDate` → ошибка; с нормальной датой — как раньше (регрессия).
4. `getDeliveryPlan`: стирка с `issue_date=''` не попадает ни в `issueToday`,
   ни в `overdueIssue` (регрессия на строковое сравнение).
5. `updateIssueDate` на стирке с пустой датой → ставит дату, создаёт визит
   (регрессия моста «назначить позже»).

## Критерии приёмки

- Стирка работника после завершения лежит на складе как «На складе»: не
  краснеет, не в «Требует решения», не в «просроченной выдаче» развоза.
- Владелец при добавлении стирки выбирает «дата выдачи» или «просто
  постирать»; оба пути работают.
- Назначение даты с карточки склада по-прежнему создаёт визит развоза.
- Стирки из плана развоза имеют дату визита и при просрочке краснеют, как
  раньше.
- Отчёт дня, сводка, счёт — без изменений. Существующие тесты зелёные.

## Что НЕ входит

- **Разбор существующих просроченных стирок** (6 на production): владелец
  разбирает руками через карточку склада — выдать / изменить дату / удалить.
  Миграции и очистки кодом не делаем.
- Массовое снятие дат со старых стирок без визитов (если захотим — отдельный
  разговор, одноразовым скриптом).
- Автоподстановка даты при появлении визита (визит на клиента со складским
  запасом по-прежнему создаст planned-стирку, которую работник закроет через
  проверку склада «есть чистое» — с P8 этот путь валидирован).

## Оценка

Полдня с тестами. Порядок: части 3–4 (серверные стражи) → 1–2 (запись) → 5
(UI склада) → UI владельца.

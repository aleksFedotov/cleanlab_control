# P3. Зарплаты: авторасчёт по точкам (водитель) и табелю (работники)

> По `docs/spec.md` + тикет P2 (подъёмы). Данные уже собираются: точки развоза —
> из `Deliveries` (как `getDeliveryPointStats`), часы работников — из `WorkHours`,
> подъёмы — из `Deliveries.lift_floor` (P2). Зарплата — слой-интерпретация над
> существующими данными, новых действий от персонала не требует.

## Принятые решения (контекст)

- **Водитель**: `точки × ставка_за_точку + доплата_за_подъёмы`.
  Сейчас водитель пишет отчёт руками («20 точек +300р») — система воспроизводит
  его автоматически. Точка = **любой** выполненный визит, включая «только забрать
  грязное» (та же логика, что `getDeliveryPointStats`: закрыт хотя бы один трек —
  `delivered_at` или `picked_at`; `empty`/`cancelled` не считаются).
- **Доплата за подъём — 100 ₽ за каждый этаж выше второго, единая для всех
  водителей** (дефолт прачки): «+300р» в отчёте — это 3 этажа суммарно (хоть
  3 этажа у одного клиента, хоть по этажу у трёх). Этажи = `lift_floor − 2`
  по визитам с `lift_floor > 2` (P2). Не путать с биллингом клиента: в счёт
  клиенту подъём идёт по тарифу прачки (P2), оплата водителю — отдельный слой
  со своей ставкой.
- **Работники цеха**: по табелю — `ставка_смены / норма_часов × отработано_часов`.
  Ставка **4000 ₽ за 12 часов, единая для всех работников** (дефолт прачки).
  Часы — из `WorkHours` (работник отмечает сам, владелец может править).
- **Ставки — дефолты прачки** (per-tenant Settings); таблица `PayRates` хранит
  только индивидуальные переопределения (ставка за точку у водителя — своя,
  остальное обычно не заполнено).
- **Округление — один раз на итоге периода**, до целых ₽ (не по дням).
- **Ручные корректировки** (премия/штраф/доплата) — таблица `PayAdjustments`,
  строка = сумма со знаком + комментарий + дата. Закрывает и случаи, которые
  система пока не считает сама (например, подъёмы до внедрения P2).
- Владелец в расчёте не участвует. Период — произвольный (месяц по умолчанию).

## Схема (SCHEMA_VERSION → 5, все значения TEXT)

### Дефолтные ставки — per-tenant `Settings`

```
PAY_POINT_RATE    (250)           — за точку развоза, дефолт для водителей
PAY_LIFT_FLOOR_RATE (100)         — за этаж выше 2-го, единая для водителей
PAY_SHIFT_BASE    (4000)          — ставка смены работника
PAY_SHIFT_NORM_HOURS (12)         — норма часов смены
```

### `PayRates` (индивидуальные переопределения, per-tenant через laundry_id)

```
id (pr_<n>), user_id, point_rate, lift_floor_rate, shift_base, shift_norm_hours, laundry_id
```

- Пустое поле = действует дефолт прачки из Settings. Одна строка на сотрудника
  (upsert по user_id); чаще всего заполнен только `point_rate` водителя.

### `PayAdjustments` (ручные корректировки)

```
id (adj_<n>), user_id, date, amount, comment, created_by, created_at, laundry_id
```

- `amount` со знаком (`+500` премия / `-300` штраф); попадает в период по `date`.

## Правила расчёта (`computePayroll_`, чистая функция в `core.js`)

**Ставки** разрешаются по цепочке: строка `PayRates` по `user_id` (непустое поле) →
дефолт прачки из `Settings`. Все дефолты заданы (250 / 300 / 4000 / 12), поэтому
«ставка не задана» — аномалия (если дефолт стёрли в Settings): сотрудник попадает
в расчёт с нулевой суммой и пометкой `rate_missing`, молча не пропускаем.

**Водитель** за период [from, to]:
- `points` — выполненные визиты прачки за период (правило `getDeliveryPointStats`:
  закрыт хотя бы один трек, `empty`/`cancelled` не считаются; визит «только забор»
  — тоже точка). На прачке один водитель, привязки к user_id нет — как в workhours.js;
- `lift_floors` — суммарные этажи подъёмов: `Σ(lift_floor − 2)` по визитам с
  `lift_floor > 2` (3-й этаж = 1, 4-й = 2, 6-й = 4). «+300р» в отчёте — это
  3 этажа × 100 ₽, распределение по клиентам не важно;
- `total = points × point_rate + lift_floors × lift_floor_rate + Σ adjustments`.

**Работник** за период:
- `hours = Σ WorkHours.hours` за период (записи `work`/`rest`/`bonus` с пустыми
  часами в зачёт не идут — по контракту WorkHours);
- `total = shift_base / shift_norm_hours × hours + Σ adjustments`
  (при дефолтах — `4000 / 12 × часы`, текущая формула).

**Округление** — один раз, на итоге периода: `Math.round(total)` до целых ₽.
Дневная разбивка — без округления (для проверки).

**Результат** `getPayroll(token, from, to)`:

```
{ from, to,
  employees: [{ user_id, name, role,
    points, lift_floors, hours,      // что насчитано
    point_rate, lift_floor_rate, shift_base, shift_norm_hours,
    amount_points, amount_lifts, amount_shift, adjustments_total,
    total,                           // округлённый итог периода, целые ₽
    rate_missing,                    // true, если не нашлась ставка
    days: [{ date, points, lift_floors, hours, amount }] }] }  // раскрытие по дням
```

## API (`api.js` или отдельный `payroll.js`, owner-only, события в `Log`)

- `getPayroll(token, from, to)` — расчёт по всем сотрудникам прачки.
- `listPayRates(token)` / `savePayRate(token, userId, fields)` — ставки
  (проверка: сотрудник принадлежит прачке сессии).
- `savePayAdjustment(token, userId, date, amount, comment)` /
  `deletePayAdjustment(token, adjId)`.
- События: `payrate_set`, `pay_adjust`, `pay_adjust_del`.

## UI

- **Владелец → новая вкладка «Зарплата»**: DateNav/период (месяц по умолчанию),
  таблица сотрудников: ставка, точки/часы, подъёмы, корректировки, итого;
  строка раскрывается по дням. Кнопка «+ Корректировка».
- **Сотрудники**: в карточке пользователя — блок ставок (по роли: точки+подъём
  у водителя, смена+норма часов у работника).
- **Водитель (опционально)**: в своём экране видит авто-отчёт за период
  («20 точек + 300 ₽ подъёмы») — заменяет ручные сообщения владельцу.

## Тесты (`server/test/payroll.test.js`, `node --test`)

- Водитель по дефолтам прачки: 20 точек × 250 + 3 этажа × 100 = 5300
  (воспроизводит отчёт «20 точек +300р»).
- Точка — любой визит с закрытым треком: «только забор» (pickup_only) считается,
  `empty`/`cancelled` не считаются.
- Подъёмы по этажам: 3-й этаж = 100 ₽, 4-й = 200 ₽, 6-й = 400 ₽; этаж ≤ 2 не
  считается; распределение не влияет (3 этажа у одного клиента = по этажу у трёх);
  индивидуальный override из PayRates перекрывает дефолт.
- Индивидуальная ставка: у водителя в PayRates `point_rate=280` → точки считаются
  по 280, остальное — по дефолтам прачки.
- Работник по дефолтам: 4000/12 × 7,5 ч = 2500; часы из WorkHours, правки
  владельца учитываются.
- Округление: часы 7,55 → сумма 2516,66… → итог периода 2517 ₽ (округление один
  раз, в конце; не по дням).
- Корректировки: +/− попадают в период по дате, вне периода — нет.
- Права: worker/driver → «Нет доступа»; чужая прачка не видна.
- Стёртый дефолт в Settings (нет PAY_POINT_RATE) — водитель в списке с нулевой
  суммой и `rate_missing=true`, молча не пропускаем.

## Оценка

2–3 дня: `computePayroll_` + тесты (1 д), API + PayRates/PayAdjustments (0,5 д),
вкладка «Зарплата» и блок ставок (1 д), отчёт у водителя (опционально, 0,5 д).

## Зависимости и отложено

- Зависит от P2 в части `lift_floor`; до P2 подъёмы ведутся корректировками.
- Отложено: выгрузка ведомости (печать/PDF), авансы/выплаты и остаток к выплате,
  сдельная оплата работников за кг/шт (spec §14 — «поштучная детализация» не берём),
  несколько водителей на прачке (привязка точек к user_id).

## Уточнение на старте реализации

- Ставка 100 ₽/этаж выведена из отчёта «+300р» = 3 этажа суммарно. Если
  фактическая цена этажа другая — меняется только значение `PAY_LIFT_FLOOR_RATE`
  в Settings, логика расчёта не трогается.

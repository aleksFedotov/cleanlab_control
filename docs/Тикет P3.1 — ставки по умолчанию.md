# P3.1. Зарплаты: редактирование дефолтных ставок прачки + опечатка в тикете P3

> Доработка к P3 (коммит 74f7075, ветка `feature/p2-invoices`). Найдено при
> проверке реализации против тикета P3: два пробела — один функциональный
> (нет UI для дефолтных ставок), один документный (опечатка).

## Проблема

1. **Дефолтные ставки прачки не редактируются из интерфейса.** Ставки
   разрешаются цепочкой PayRates → Settings (`PAY_*`) → встроенный дефолт
   (250/100/4000/12). Индивидуальные переопределения владелец меняет в карточке
   сотрудника (`savePayRate`), а поменять дефолт сразу для всех — например,
   поднять точку с 250 до 260 всем водителям — можно только руками в БД.
   В тикете P3 этот блок был (методы `listPaySettings`/`savePaySettings`,
   блок «Ставки по умолчанию»), при реализации выпал.
2. **Опечатка в `docs/Тикет P3 — расчёт зарплат.md`**: в разделе «Правила
   расчёта» написано «Все дефолты заданы (250 / **300** / 4000 / 12)» —
   должно быть **100** (ставка за этаж). Код правильный, путается читатель.

## 1. Блок «Ставки по умолчанию»

### Сервер (`server/payroll.js`, регистрация в `api.js`)

- `listPaySettings(token)` → `ok({ settings: { point_rate, lift_floor_rate,
  shift_base, shift_norm_hours } })` — действующие значения прачки: из Settings,
  если ключ задан, иначе встроенный дефолт. Owner-only.
- `savePaySettings(token, fields)` — owner-only. Принимает только 4 ключа
  `RATE_DEFAULTS`, остальное игнорирует. Валидация как в `savePayRate`:
  неотрицательное число.
- **Важно про пустое значение:** пустое поле = **удалить ключ** из Settings
  (возврат к встроенному дефолту), а **не** записать `''`. Записанная пустая
  строка для `resolveRate_` — «стёртый дефолт» → `rate_missing=true` у всех
  сотрудников без override. Использовать удаление ключа, а не
  `setTenantSetting_(id, key, '')`.
- Событие в `Log`: `pay_settings_set` (поля + значения).
- Пересчёт задним числом — известное поведение P3 («расчёт на лету по текущим
  ставкам»), в UI рядом с блоком — короткая подсказка: «новые ставки применяются
  ко всем периодам, прошлые месяцы пересчитаются».

### UI (`(dashboard)/payroll/page.tsx`)

- Сверху страницы «Зарплата» — сворачиваемый блок «Ставки по умолчанию»
  (можно на `ui/Accordion.tsx` из P2.1): четыре поля — «За точку, ₽»,
  «За этаж подъёма, ₽», «Ставка смены, ₽», «Норма часов смены».
- Сохранение onBlur (как в прайсе клиента) или одной кнопкой «Сохранить» —
  на выбор по консистентности со страницей; после сохранения инвалидировать
  `payroll`, `payRates`, `myPayroll`.
- Подсказка под блоком: «Персональные ставки — в карточке сотрудника
  (раздел «Сотрудники»); пустое поле здесь = встроенный дефолт
  (250 / 100 / 4000 / 12)».

### Тесты (`server/test/payroll.test.js`, `node --test`)

- `savePaySettings`: точка 300 → водитель без override считается по 300,
  водитель с override в PayRates — по своему.
- Пустое значение удаляет ключ → действует встроенный дефолт 250,
  `rate_missing=false` (а не «стёртый дефолт»).
- Нечисло / отрицательное → ошибка, настройка не меняется.
- Права: worker/driver → «Нет доступа»; событие `pay_settings_set` в Log.
- Тенантность: `PAY_POINT_RATE` прачки 2 не влияет на расчёт прачки 1.

## 2. Опечатка в тикете P3

`docs/Тикет P3 — расчёт зарплат.md`, раздел «Правила расчёта»:
«Все дефолты заданы (250 / 300 / 4000 / 12)» → «(250 / **100** / 4000 / 12)».
Одна строка, можно тем же коммитом.

тесты; опечатка — заодно.

# Тикет P2.4 — «Как добраться»: подсказка водителю на карточке клиента

**Ветка:** от master (SCHEMA_VERSION сейчас 7 → станет 8)
**Оценка:** 0,5–1 день
**Связь:** P2.3 (страница клиента), экран водителя `client/src/app/driver/page.tsx`

## Проблема

Водитель приезжает к клиенту и не может попасть внутрь: клиент во дворе, на калитке кодовый замок, вход через арку, нужно звонить охране. Адреса в карточке мало — нужна живая текстовая подсказка «как пройти», которую пишет владелец, а водитель читает в момент прибытия на точку.

## Что делаем

1. **Новое поле у клиента** — свободный текст (не окно, обычное текстовое поле) с описанием, как добраться/пройти: арка, код калитки, подъезд, куда звонить, где поставить машину.
2. **Экран водителя** — на точке маршрута появляется кнопка «Как пройти»; по нажатию показывается текст, который написал владелец.
3. Никакой структуры у текста нет: одно поле, переносы строк сохраняются, валидации нет.

## Названия (предложение)

| Место | Название | Почему |
|---|---|---|
| Поле в карточке клиента (владелец) | **«Как добраться»** | Шире, чем «проход»: сюда же парковка, заезд, ориентиры. Владелец пишет в спокойном контексте редактирования. |
| Кнопка у водителя | **«Как пройти»** | Водитель читает её в момент, когда стоит у двери — формулировка-действие под задачу «зайти прямо сейчас». Иконка `KeyRound` (код/ключ) — `MapPin` и `Phone` на экране уже заняты. |
| Колонка в БД / поле API | `access_note` | Нейтрально, не конфликтует с `comment`. |

Альтернативы, если не нравятся: поле — «Как пройти к клиенту», «Подсказка водителю»; кнопка — «Как добраться», «Проход и коды».

Плейсхолдер поля у владельца (подсказывает, что писать):
> Арка со двора, код калитки 4321, 2-й подъезд, звонить охране…

## Сервер

### 1. Схема: SCHEMA_VERSION 7 → 8

- `Clients` HEADERS: добавить `access_note` в конец (после `laundry_id`) — все значения TEXT, как везде.
- `migrateToV8_`: добавить колонку существующей таблице, старым строкам — `''` (дефолт). Миграция идемпотентна (проверка через `readAll_`/`PRAGMA table_info`, как предыдущие миграции — повторный запуск не падает и не дублирует).
- Новые клиенты без заполненного поля → `''`.

### 2. API

- `saveClient`: принять `access_note` в пейлоаде (добавить в список сохраняемых полей, если там whitelist). Нормализация: `trim`, лимит **2000 символов** (больше — обрезать или 400; выбрать обрезку с trim, чтобы не ломать автосохранение). Логируется существующим событием сохранения клиента, новое событие не нужно.
- `getRefs`/выдача клиентов: поле уедет автоматически вместе со строкой.
- **`getDriverRoute`**: в каждый объект визита добавить `access_note` (join/подмешивание из `Clients` там же, где сейчас подмешиваются `client_name`/`address`/`contact`). Клиента без подсказки → `''`.
- Права: меняют поле только owner (существующая проверка `saveClient`). Водитель получает подсказки только клиентов своего маршрута — тенант-фильтрация маршрута уже есть, ничего дополнительно не проверяем.
- Дублирование клиента (меню «⋯» → «Дублировать» на странице клиента): поле копируется в пейлоад дубля.

### 3. Типы

- `types/api`: `DriverRouteRes['visits'][number]` += `access_note?: string` (по образцу того, как `contact` уже до-типизирован локально в driver/page.tsx — лучше сразу внести в общий тип и убрать локальный костыль для `contact` заодно, по желанию).

## Клиент — страница клиента (владелец)

`client/src/app/(dashboard)/refs/clients/[id]/page.tsx`, вкладка **«Профиль»**:

- Текстовое поле **«Как добраться»** (textarea, 3–4 строки, авто-рост не обязателен) — сразу после поля «Адрес» (по смыслу пара), до «Комментарий».
- Механика — как у остальных полей профиля: в `fields`-стейт, в список `blur(...)`-сравнения, сохранение по `onBlur` через существующий `saveField` (полный пейлоад с подменённым полем). Отдельной кнопки «Сохранить» нет, индикатор «Сохранение… / ✓ Сохранено» работает сам.
- `maxLength={2000}` на textarea.
- Если создание клиента идёт отдельной формой — то же поле туда.
- Пустое значение — норма, никаких предупреждений.

## Клиент — экран водителя

`client/src/app/driver/page.tsx` (экран «Маршрут»):

1. **Индикатор на карточке точки** (список «Адреса»): если `access_note` непуст — маленькая иконка `KeyRound` рядом с именем клиента (или в конце метастроки). Чтобы водитель видел наличие подсказки ещё до открытия точки.
2. **Кнопка в модале точки** (та, что открывается по тапу на карточку, `visitTarget`): если `access_note` непуст — под метастрокой ghost-кнопка **«Как пройти»** с иконкой `KeyRound`. По нажатию — раскрывается инлайн-блок с текстом (`white-space: pre-wrap`, заметный фон, крупный читаемый шрифт). Повторное нажатие сворачивает. Состояние «раскрыто» сбрасывается при закрытии модала.
3. **Пусто → ничего нет**: ни иконки, ни кнопки, ни «подсказки нет» — экран не засоряем.
4. Вкладка «История» — без кнопки (там подсказка не нужна; если тривиально — можно, опционально).

Важно: водительский экран — именно `app/driver/page.tsx`, а не дашбордовский `(dashboard)/delivery/page.tsx` (это экран «Развоз» владельца). На странице «Развоз» у владельца подсказку **опционально** можно показать в деталях визита (в `visitDetails` или по иконке) — по остаточному принципу, отдельным мелким пунктом; критичен только экран водителя.

## Граничные случаи

- Подсказка есть, клиент архивный → в маршрут не попадает вместе с клиентом, поле просто хранится.
- Очень длинный текст → лимит 2000 на клиенте (maxLength) и сервере.
- Текст содержит коды домофонов — это осознанно: видят водители этой прачки, у которых клиент в маршруте. В тикете-описании поля у владельца можно мягко намекнуть: «видят водители» (хинт под полем, одна строка).
- Мультитенантность: утечек нет — водитель прачки Б не получает маршруты/подсказки прачки А (покрыто существующей фильтрацией `getDriverRoute`, держим регрессионный тест).

## Тесты

**Сервер (`server/test/…`):**
- Миграция v8: колонка появилась, старые строки получили `''`, повторный прогон миграции не падает (идемпотентность), изоляция тенантов не сломана.
- `saveClient`: round-trip `access_note` (сохранил → прочитал); >2000 символов обрезается; пустая строка сохраняется; driver/worker не могут вызвать `saveClient` (существующая проверка прав — регрессия).
- `getDriverRoute`: у визита есть `access_note` с текстом клиента; клиент без подсказки → `''`; изменение поля отражается в следующем запросе маршрута (без кэша).

**Клиент (по возможности Playwright / вручную):**
- Страница клиента: ввёл текст → blur → «✓ Сохранено»; перезагрузка — текст на месте.
- Экран водителя: точка с подсказкой — есть иконка и кнопка «Как пройти», раскрывает текст с переносами строк; точка без подсказки — ни иконки, ни кнопки.

## Критерии приёмки

1. Владелец на странице клиента заполняет «Как добраться», текст сохраняется автоматически (onBlur), переживает перезагрузку.
2. Водитель в маршруте дня видит у такой точки иконку, тапает точку → кнопка «Как пройти» → читает текст.
3. Точка без подсказки выглядит ровно как раньше — ничего лишнего.
4. Дублирование клиента копирует подсказку.
5. Миграция v8 идемпотентна; старые клиенты без подсказки работают как прежде.

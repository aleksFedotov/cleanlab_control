# Тикет P7 — секция «Осталось с прошлых дней» на экране работника

**Ветка:** от master
**Оценка:** 0,5 дня
**Файлы:** `server/api/washes.js` (getDayList), `client/src/app/worker/page.tsx`, типы, тесты

## Проблема

Экран работника — всегда «сегодня», переключателя даты у него нет. Стирка привязана к своей `wash_date` и сама никуда не переезжает: если вчера что-то не достирали (забыли, не хватило времени, бельё привезли поздно), после полуночи эти карточки для работника **исчезают**. Дожать их может только владелец (переключатель даты на «Стирке» или «Перенести»), а ночная/утренняя доработка без владельца невозможна.

## Решение

На экране работника появляется секция **«Осталось с прошлых дней»** — все незавершённые стирки с `wash_date` раньше сегодняшнего, с теми же действиями, что у обычных карточек. Работник дожимает их на месте: стартует, завершает, переносит, удаляет — без владельца и без перелистывания дат.

Ключевое решение: **стирка остаётся на своей исходной дате** (`wash_date` не меняем при завершении) — она была запланирована туда, в отчёт и дайджест того дня и должна попасть. Если нужно перенести — для этого есть явное действие «Перенести» (deferWash), оно и оставляет след (`deferred_from`).

## Сервер (`getDayList`)

1. В ответ добавить массив **`overdue`**: стирки прачки с `wash_date < date` и статусами `planned`, `no_linen`, `in_progress`, а также `partial` **кроме** решённых «оставить на складе» (`deferred_reason === 'hold'` — владелец уже разобрался, не мусорим). Терминальные (`issued`, `cancelled`) и завершённые (`done`/`stored`/`ready_clean`) не включаем — с ними делать нечего.
2. Сортировка: по `wash_date` по возрастанию (самые старые сверху — они срочнее).
3. Декорация как у обычных карточек дня: `client_name`, `has_dirty`/`has_clean` (сводка склада уже считается в getDayList), `partial_rest`/`prev_items`/`prev_kg`/`prev_bags`, `piece_types`. Логика общая — вынести/переиспользовать, не копипастить.
4. Действия — **никаких серверных изменений**: `startWash`, `completeWash`, `deferWash`, `deleteWash`, `confirmStorageCheck` дату и статус смены не проверяют и с прошлодневной стиркой работают как есть.
5. Закрытие смены: `shiftBlockers_` смотрит только на сегодня — просроченные стирки сегодняшнее закрытие не блокируют (и не должны).

Известные граничные поведения (осознанно, не чиним в этом тикете):
- `startWash` по старой дате вызовет `ensureShift_(wash_date)` — если смены того дня не было, она создастся **открытой** и закрыть её через UI уже нельзя (`closeShift` работает только на сегодня). Последствие: работник сможет править завершённые стирки того дня (`canEditWashData_` увидит open). Приемлемо; отдельная история про `reopenShift` — вне scope.
- Завершение вчерашней стирки ставит `done_at = сейчас`, но стирка остаётся во вчерашнем отчёте (`buildDayReport_` по `wash_date`) и вчерашнем счёте — правильно.

## Клиент — экран работника (`worker/page.tsx`)

1. Секция **`«Осталось с прошлых дней (N)»`** — самой первой, над «Сейчас в работе» (это долг, глаза должны цепляться сразу). Визуально приглушить/оттенить warn-цветом, чтобы не путать с сегодняшней очередью.
2. Карточки — переиспользовать `QueuedWashCard`/`ActiveWashCard`, добавив **чип даты** «от 03.09» (`formatDateRu(w.wash_date, false)`) рядом с именем или бейджем статуса. Действия те же: «Начать стирку» / «Завершить стирку», «Перенести», «Удалить», «Проверить на складе».
3. После любого действия — существующая инвалидация `operational`, карточка уезжает из секции (при завершении — в отчёт своей даты; при переносе на сегодня — в сегодняшнюю очередь).
4. Поиск по клиенту должен фильтровать и эту секцию (общий список `visible` сейчас строится из `washes` — включить `overdue` в ту же фильтрацию).
5. Пустой секции не бывает: `overdue.length === 0` → секцию не рендерим вовсе.
6. Статистика в шапке (`В работе / В очереди / Готово`) — только про сегодня, просроченные не считаем (иначе «В очереди 5» при пустом сегодняшнем дне будет путать).

**Владельцу на «Стирке» (/wash) секция не нужна** — у него есть переключатель даты. (Опционально, если тривиально: бейдж-напоминание «с прошлых дней осталось: N» на сегодняшней доске. По остаточному принципу, можно отрезать.)

## Тесты

**Сервер (`server/test/…`):**
- `getDayList` на сегодня: вчерашняя `planned`/`no_linen`/`in_progress`/`partial` — в `overdue`; `partial` с `deferred_reason='hold'` — не в `overdue`; завершённые и терминальные — не в `overdue`; сегодняшние — в `washes`, не дублируются в `overdue`.
- Декорация overdue: `client_name`, флаги склада, `partial_rest` проставлены.
- Сквозной сценарий: вчерашняя planned → `startWash` → `completeWash` работником — успех; `wash_date` не изменилась; стирка попала во вчерашний отчёт, в сегодняшний — нет; clean-запись склада создана.
- `deferWash` вчерашней на сегодня → стирка в сегодняшних `washes`, из `overdue` исчезла.
- `closeShift` сегодня не блокируется наличием просроченных стирок.

**Клиент (вручную / e2e `worker`-сценарий):**
- Вчерашняя недоделанная стирка видна в секции с чипом даты → завершить → секция опустела, в «Готово» сегодня она не появилась.
- «Перенести» на сегодня → карточка в сегодняшней очереди.

## Критерии приёмки

1. Работник видит все незавершённые стирки прошлых дней отдельной секцией с датой на карточке.
2. Может их начать/завершить/перенести/удалить без владельца и без переключения дат.
3. Завершённая «вчерашняя» стирка остаётся в отчёте и счёте своей исходной даты.
4. Секция пуста → не отображается; сегодняшние счётчики в шапке просрочку не учитывают.

> **Статус: миграция завершена.** VPS-версия (`server/`, Express + SQLite) — единственная; GAS-версия (`src/*.gs`) удалена из репозитория. Поверх добавлена мультитенантность (таблицы `Laundries`/`Users`, `laundry_id` в операционных таблицах, per-tenant TV-ключи и Telegram-чаты). Документ оставлен как историческая запись плана; актуальное состояние — в `docs/spec.md` и `docs/deploy.md`.

Статус на момент плана: **Этап 2 выполнен** (ветка `vps-migration`, монорепо): бэкенд перенесён в `server/` (Express + SQLite), фронт — `server/public/` с fetch-адаптером, Telegram — `/telegram/webhook`, 41 тест нового слоя + 65 GAS-тестов зелёные. Дальше: этап 1 (VPS/домен/Caddy) и этап 3 (миграция данных).

## Принятые решения (итоги обсуждения)

- **Домен**: нужен практически наверняка — HTTPS обязателен для Telegram webhook/WebApp. Варианты: дешёвый домен (.ru ~300 ₽/год) или бесплатный субдомен DuckDNS. Сертификат — Let's Encrypt, бесплатно.
- **Стек**: Node.js (Express/Fastify) + SQLite + Caddy (авто-HTTPS). Фронтенд — существующий `src/Index.html` как статика, без React.
- **Порядок этапов**: 1) перенос как есть на JS → 2) стабилизация → 3) TypeScript для бэкенда → 4) (возможно, позже) React для фронта.
- **Ресурсы**: ~150 МБ RAM на весь проект — на 8 ГБ VPS с чат-ботами и AI-агентами незаметно.
- **Изоляция на сервере**: отдельный systemd-сервис или Docker-контейнер, автоперезапуск через systemd/PM2.

## Контекст текущей системы

- Репо: `cleanlab_control`, ветка master, GitHub `aleksFedotov/cleanlab_control`.
- Бэкенд: `src/*.gs` (Api, Core, Db, Storage, Auth, Audit, Backup, Deliveries, Main, Telegram и др.), схема листов — `src/Schema.gs` (HEADERS).
- Фронт: `src/Index.html` — 5 вкладок (Цех, Неделя, Развоз, Склад, Клиенты), ванильный JS, `google.script.run`.
- Тесты: `tests/*.test.js`, 53 теста, `npm test`. Они станут проверкой при переносе.
- Telegram-бот через webhook + Cloudflare-прокси (`cf-webhook-proxy/`) — после переезда прокси не нужен, webhook укажет прямо на VPS.

## Этап 1. Подготовка VPS

1. Арендовать/подготовить VPS (Ubuntu LTS), публичный IP.
2. Зарегистрировать домен или DuckDNS-субдомен, A-запись на IP сервера.
3. Установить: Node.js LTS, Caddy, (опционально Docker).
4. Настроить Caddy: `cleanlab.example.com { reverse_proxy localhost:3100 }` + статика фронта.

## Этап 2. Перенос бэкенда (JS, без смены логики)

1. Новая директория `server/` в репо (или отдельный репо — решить при старте).
2. Слой данных: заменить SpreadsheetApp на SQLite (better-sqlite3). Таблицы = листы из Schema.gs, колонки = HEADERS. Модуль `db.js` с тем же интерфейсом, что `Db.gs` (readAll/append/update по id).
3. Перенести Core.gs, Storage.gs, Deliveries.gs, Audit.gs, Auth.gs почти 1-в-1 (чистый JS).
4. Api.gs → HTTP-эндпоинты Express: каждая функция api-метода = POST `/api/<method>`. Замена `google.script.run` на `fetch` во фронте (небольшая обёртка-адаптер, чтобы не переписывать весь Index.html).
5. Telegram: webhook-эндпоинт `/telegram/webhook`, перенос логики из Telegram.gs; setWebhook на новый URL. Cloudflare-прокси выводится из схемы.
6. Аутентификация: PIN-коды — тот же механизм, хранение в БД.

## Этап 3. Миграция данных

1. Экспорт из Google-таблицы: скрипт в GAS, выгружающий все листы в JSON (по HEADERS).
2. Импорт в SQLite: скрипт `migrate.js`, создаёт таблицы и заливает JSON.
3. Проверка: сверка количества строк и выборочных значений по каждой таблице.

## Этап 4. Тестирование и параллельный запуск

1. Прогон существующих тестов против нового слоя данных (адаптировать хелперы tests/helpers).
2. Ручная проверка всех вкладок и user flow (owner/worker/driver, склад, неделя, развоз).
3. Параллельная работа: GAS-система остаётся живой, пока VPS-версия не подтверждена.

## Этап 5. Переключение

1. Финальная синхронизация данных (повторный экспорт/импорт дельты).
2. Переключение пользователей на новый URL; Telegram webhook — на VPS.
3. GAS-развёртывание перевести в read-only/архив. Бэкап таблицы (Backup.gs) — финальный.

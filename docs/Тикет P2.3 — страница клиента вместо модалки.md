# P2.3. Страница клиента вместо модалки («Справочники»)

> Дополнение к P2.1. Аккордеоны сняли визуальный шум, но не главную проблему:
> в модалке по-прежнему живут три разные задачи (профиль, прайс, привязки),
> у клиента нет URL, а таблицы цен и привязок зажаты в панель 480px. Цель:
> отдельная страница клиента с вкладками, короткая модалка только для
> создания. Сервер и API не меняются — только клиентская часть.

## Проблема (зафиксировано по коду `refs/client-form.tsx`)

1. **Нет URL у клиента.** Модалка не даёт deep-link: из счёта/визита нельзя
   сослаться на клиента. Для P4 (Финансы) ссылки на клиента обязательны.
2. **Контент перерос контейнер.** Спека: Modal — max-width 480px. Прайс
   (строка на позицию) и привязки (строка на вид белья) — это DataTable-контент,
   он в 480px не помещается: скролл внутри скролла, колонки сплюснуты.
3. **Шум автосохранения.** `SavedMark` («✓ Сохранено») мерцает у каждого
   поля — 10+ самозатухающих индикаторов на форме. Статус сохранения должен
   быть один на страницу.
4. **Тихие состояния не тихие.** Бейдж «наследовано» висит на большинстве
   строк прайса, хотя наследование — дефолт. Информировать нужно только об
   отклонениях.
5. **Контринтуитивный пустой выбор.** «Виды белья»: ничего не отмечено =
   работник видит все виды. Пустое состояние означает «всё» — это ломает
   ожидания.
6. **Деструктивное действие на виду.** «В архив» стоит в футере рядом с
   «Закрыть» — одна ударная кнопка рядом с обычной.

## Принятые решения

### 1. Страница клиента `/refs/clients/[id]`

- Новый роут `app/(dashboard)/refs/clients/[id]/page.tsx`. Из списка клиентов
  (`refs/page.tsx`) строка DataTable кликабельна: вся строка → переход на
  страницу (hover-строка по спеке — фон `--bg`, курсор pointer).
- Шапка: хлебные крошки «Справочники / Клиенты / ‹имя›» (12.5px `--text-3`,
  разделитель `/`, ссылки hover `--text`), заголовок 18–20px/800 (по спеке
  PageHeader), рядом StatusBadge-стиль пилюля с типом клиента (нейтральная:
  `--neutral` / `--neutral-bg`). Справа в шапке — **единый индикатор
  сохранения** (п. 4) и меню «⋯».
- Контент — `max-width: var(--content-max)`, padding 24–28px, как у остальных
  страниц дашборда.
- Меню «⋯` (иконка `more-horizontal`, lucide): «Дублировать», разделитель,
  **«В архив»** (danger `--danger`, с ConfirmDialog — как удаление в
  справочниках). Кнопки «В архив» в футере больше нет — футера нет вообще,
  страницу не нужно «закрывать».

### 2. Вкладки: Профиль / Цены / Привязки

- Новый компонент `ui/Tabs.tsx` (в ките его ещё нет). Стиль: ряд подчёркнутых
  вкладок на нижней границе `--border`; активная — текст `--bluing` + линия
  2px `--bluing` снизу, неактивные — `--text-2`, hover — `--text`. Шрифт 14px,
  активная 600. На узких экранах вкладки скроллятся горизонтально (как
  FilterPills).
- В подписи вкладок — сводки из P2.1 (не пересчитываем заново, используем
  `pricesSummary`/счётчик привязок): «Цены · 2 переопределены · 1 без цены»,
  «Привязки · 2 настроены». Сводка 12px `--text-4`.
- Активная вкладка — в query-параметре `?tab=prices|bindings` (default —
  профиль, параметр не пишем). Это задел под ссылки из Финансов (P4):
  «Открыть счёт клиента» сможет вести сразу на нужную вкладку.
- **Профиль**: основные поля (название, тип, адрес, контакт, комментарий),
  свёрнутые «Реквизиты» (Accordion из P2.1 со сводкой — остаётся как есть),
  «Виды белья» (п. 5), «Учёт результата» (п. 6).
- **Цены**: `ClientPricesSection` без изменений логики — сортировка
  (переопределённые → с дефолтом → без цены), видны важные, остальные под
  «Показать все позиции (N)». Оформление строк — по DataTable из спеки:
  разделители `--border` без зебры, шапка 12px uppercase `--text-4`, числа —
  JetBrains Mono, tabular-nums, вправо. Бейджи: только **«переопределено»**
  (текст `--bluing`, фон `--bluing-soft`) и **«не задана»** (`--warn` /
  `--warn-bg` — дыра в счёте, должна бросаться в глаза). Бейдж «наследовано»
  удаляется — наследованные строки визуально тихие.
- **Привязки**: `ClientBindingsSection` без изменений логики — видны явные
  привязки, остальные под «Настроить по видам (N)». Оформление строк — как
  у Цен.

### 3. Модалка создания — только минимум

- Модалка остаётся, но урезается до трёх полей: **Название\***, **Тип**,
  **Контакт**. Реквизиты, виды белья, учёт — убираются: значения по умолчанию
  (`type: отель`, `accounting: both`, `item_types: []` = все виды) покрывают
  90% случаев, остальное настраивается на странице после создания.
- По спеке Modal: max-width 480px, `radius-xl`, `shadow-pop`, оверлей
  `rgba(15,23,42,.4)` + blur 4px, заголовок 17px/800. Под заголовком —
  подпись 12.5px `--text-3`: «Остальное настроите позже в карточке клиента».
- Футер: «Отмена» (subtle) + «Создать» (primary, busy при мутации).
  zod-валидация названия как сейчас. После создания — переход на страницу
  нового клиента (`router.push`), а не просто закрытие: пользователь сразу
  может донастроить, toast «Клиент создан» (по спеке — белая карточка,
  зелёная полоса слева).
- Поля с label сверху (13.5px, `--text-2`), не placeholder-as-label: при
  заполнении подпись пропадает и поле не опознать.

### 4. Единый индикатор автосохранения

- `SavedMark` у каждого поля **удаляется**. Вместо него — один статус в
  шапке страницы, справа от заголовка: «Изменения сохраняются
  автоматически» (idle, 12px `--text-4`) → «Сохранение…» (мутация в полёте)
  → «✓ Сохранено · 14:32» (время — JetBrains Mono, галочка `--ok`).
- Механика сохранения не меняется: текст по `onBlur` (если изменилось),
  селекты/переключатели по `onChange`, полный payload с подменой поля.
  Валидация ИНН/КПП на клиенте до отправки — остаётся, ошибка — красный
  текст 12.5px под полем (`--danger`).

### 5. Виды белья: явный режим вместо «пусто = всё»

- Сверху секции — два чипа в стиле FilterPills: **«Все виды белья»** /
  **«Только выбранные»**. Активный чип — заливка `--bluing`, белый текст.
- «Все виды»: подпись 12.5px `--text-3` — «Работник увидит все активные
  виды — ограничений нет», список не показывается.
- «Только выбранные»: виды — чипсами (тот же стиль FilterPills, активный =
  выбран), под списком счётчик «Выбрано: N из 12». N=0 — предупреждение:
  «работник не увидит ни одного вида».
- Маппинг на данные без изменений: «Все виды» → `item_types: []`,
  «выбранные» → массив id. Миграция не нужна: пустой массив читается как
  «Все виды», непустой — как «Только выбранные».

### 6. Учёт результата — FilterPills вместо радиокнопок

Три взаимоисключающих варианта («Вес + количество» / «Только вес» /
«Только количество») — три чипа FilterPills, активный — `--bluing`. Семантика
та же (radio), вид — как фильтры по всему дашборду. Секция стоит рядом с
«Видами белья» на вкладке Профиль — это настройки приёмки, а не биллинга.

### 7. Соответствие дизайн-спецификации (чек-лист)

- Цвета только из токенов: акцент `--bluing` (#2563eb), нейтрали
  `--bg/--surface/--border/--text*`, статусы из `lib/dicts.js`. Новых
  акцентных цветов не вводим. Прототип (каркас) рисовался в нейтральной
  гамме — в реализации вся палитра строго из спеки.
- Иконки — только `lucide-react` (`more-horizontal`, `chevron-right` в строке
  списка при желании). Эмодзи в дашборде владельца запрещены.
- Радиусы/тени: карточки `radius-l` + `shadow-card`, модалка `radius-xl` +
  `shadow-pop`, чипы `radius-pill`.
- Числа и время — JetBrains Mono, `tabular-nums` (цены, счётчики, время в
  индикаторе сохранения) — цифры не «прыгают».
- Тосты ошибок API — текстом сервера; busy на «Создать» исключает двойную
  отправку.
- Состояния по спеке: страница клиента — скелетон при загрузке (профиль —
  блоки полей, вкладки — полосы), несуществующий id — Empty («Клиент не
  найден», кнопка «К списку клиентов»).
- API-контракт не меняется: `saveClient`, `saveTariff`,
  `saveClientItemBilling` — как есть.

## Затронутые файлы

- **Новые:** `refs/clients/[id]/page.tsx`, `components/ui/Tabs.tsx` (+ css).
- `refs/client-form.tsx` — расформировать: `ClientCreateModal` (п. 3),
  `ClientPricesSection`/`ClientBindingsSection` → отдельные файлы, страница
  клиента их переиспользует. `ClientEditForm` и `SavedMark` удаляются.
- `refs/page.tsx` — строка клиента кликабельна → `router.push`; кнопка
  «+ Добавить» открывает новую компактную модалку.
- `refs/refs.module.css` — стили вкладок/чипсов, если не уйдут в ui-кит.
- После **P4**: вкладка/ссылка «Счета» на странице клиента (`?tab=prices`
  уже заделан под deep-link из Финансов).

## Тесты (Playwright, `client/e2e/`)

- Список: клик по строке клиента → URL `/refs/clients/<id>`, заголовок = имя.
- Создание: в модалке только 3 поля; пустое название → ошибка, не уходит;
  «Создать» → переход на страницу клиента + toast.
- Профиль: правка «Контакт» → blur → в шапке «Сохранение…» → «✓ Сохранено»;
  обновить страницу — значение на месте. ИНН 5 цифр → ошибка под полем,
  на сервер не уходит.
- Вкладки: `?tab=prices` открывает сразу Цены; сводка в подписи вкладки
  корректна («2 переопределены»).
- Цены: у строки с переопределением — синий бейдж, у наследованной бейджа
  нет; «Показать все» раскрывает остальные; правка цены — сохранение без
  перезагрузки.
- Виды белья: переключение «Только выбранные» → чипсы; выбор двух видов →
  счётчик «Выбрано: 2 из 12»; возврат на «Все виды» → `item_types` пуст.
- «В архив» — из меню «⋯», с ConfirmDialog; после архива — бейдж «в архиве»
  в шапке, возврат в список.
- Мобильная ширина: вкладки скроллятся, горизонтального скролла страницы нет.

## Оценка

1,5–2 дня: роут + шапка + Tabs (0,5), перенос секций и единый индикатор
сохранения (0,5), компактная модалка создания + чипсы видов/учёта (0,25),
кликабельный список + e2e (0,5).

## Зависимости

- Нет (сервер не трогаем). Вкладка «Счета» и ссылки из Финансов — после **P4**;
  query-параметр `?tab=` — задел под них.

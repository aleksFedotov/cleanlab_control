# P4. «Финансы»: начисления по клиентам за период

> По тикетам P2 (счета) и P3 (зарплаты). «Сводный отчёт» вырастает во вкладку
> «Финансы»: та же таблица клиентов плюс денежный слой. «Табель» остаётся
> отдельным экраном и обрастает колонкой начислений (P3). Новых таблиц и
> миграций нет — read-only слой над `buildInvoice_` (P2) и `computePayroll_` (P3).

## Принятые решения (контекст)

- **Показываем начисления, а не долг.** Колонка — «Начислено за период»: сколько
  выходит по каждому клиенту за выбранный период. Учёта оплат нет (подтверждено:
  «просто хочется, сколько выходит у каждого клиента за период»). Поэтому
  реестр выставленных счетов и статусы оплаты **не делаем** — см. «Отложено».
- **«Финансы» = эволюция «Сводного отчёта»**, не новый экран: тот же период-
  переключатель (месяц / год / произвольный), та же таблица клиентов, к которой
  добавляются колонки рейсов, подъёмов и суммы. Роут `/summary` → `/finance`,
  со старого — редирект.
- **Табель не переезжает в Финансы.** Табель — ежедневный ввод часов, финансы —
  помесячный контроль; объединение удлинило бы ежедневную операцию ради
  помесячной. Вместо этого Табель в режиме «Месяц» получает начисления из P3.
- **Схема БД не меняется** (SCHEMA_VERSION остаётся): всё считается на лету из
  `Washes`/`WashItems`/`Deliveries` (P2) и `WorkHours`/`PayRates`/`Settings` (P3).

## Сервер: `getFinanceSummary(token, from, to)` (owner-only)

Один вызов вместо N вызовов `getClientInvoice`: данные за период выбираются
один раз (Washes со статусами done/stored/issued, WashItems, Deliveries,
прайс и тарифы), затем `buildInvoice_` прогоняется по каждому активному
клиенту прачки. Результат:

```
{ from, to,
  clients: [{
    client_id, client_name,
    washes, bags, weight_kg, items_total,   // объёмы (как getSummaryReport)
    trips,            // Σ qty по строкам kind='trip' (рейсы/плечи)
    lifts,            // Σ qty по строкам kind='lift' (факты подъёмов)
    amount,           // итог счёта, ₽ (как в getClientInvoice)
    missing_prices,   // число позиций без цены — сумма тогда занижена
    lines,            // строки счёта — для раскрытия без второго запроса
  }],
  totals: { washes, weight_kg, items_total, amount } }
```

- Клиенты без активности за период не включаются (как в сводном отчёте).
- `amount` — ровно тот же итог, что покажет печатный счёт: расхождений между
  таблицей и `/invoice` быть не должно (общий код `buildInvoice_`).
- События в `Log` не пишем — метод read-only.

## UI

### Вкладка «Финансы» (бывший «Сводный отчёт»)

- Пункт сайдбара: «Финансы», иконка `Wallet`/`CircleDollarSign` вместо `PieChart`.
- Таблица: **Клиент | Стирок | Вес | Вещей | Рейсы | Подъёмы | Начислено, ₽**.
- StatRow добавляет карточку «Начислено» (Σ amount, tone ok).
- **Подсветка неполных цен:** если `missing_prices > 0`, сумма клиента —
  оранжевой плашкой/бейджем «не все цены заданы»; итог в StatRow тогда тоже
  с пометкой. Молча заниженную сумму не показываем.
- Раскрытие строки: позиции счёта (наименование, кол-во, цена, сумма — из
  `lines`, второго запроса нет) + кнопка **«Открыть счёт»** →
  `/invoice?client=<id>&from=<from>&to=<to>` в новой вкладке (печатный вид
  уже готов в P2).
- Пустой период и ошибки — как в текущем summary (Empty + Повторить).

### Табель + начисления (после P3)

- Режим «Месяц»: у матрицы работников после колонки «Σ часов» — колонка
  **«Начислено, ₽»** (`shift_base / shift_norm_hours × часы`, по текущим ставкам).
- Блок «Развозы водителя» дополняется строкой итога:
  «Точек 47 × 250 ₽ + подъёмы 3 эт. × 100 ₽ + корректировки −300 ₽ = **11 750 ₽**».
- Кнопка «+ Корректировка» (UI корректировок из P3) доступна отсюда же.
- Режимы «День»/«Год» не трогаем: день — ввод, год — обзор часов.

## Тесты (`server/test/finance.test.js`, `node --test`)

- Суммы `getFinanceSummary` совпадают с `getClientInvoice` по тем же трём
  реальным счетам из P2 (792 кг отель, 862 кг + шторы, 422 кг фитнес).
- Клиент с позицией без цены: `missing_prices > 0`, сумма посчитана по
  оценённым строкам, клиент помечен.
- Клиент без стирок за период отсутствует в выдаче.
- `trips`/`lifts` согласованы со строками счёта (Σ qty по kind).
- Права: worker/driver → «Нет доступа»; чужая прачка не видна (tenant-фильтр).
- Пустой период → пустой список, нулевые итоги, без ошибок.

## Оценка

1–2 дня: `getFinanceSummary` + тесты (0,5–1 д), вкладка «Финансы» (0,5 д),
колонка начислений в Табеле (0,5 д, после P3).

## Зависимости и отложено

- Зависит от **P2** (`buildInvoice_`, прайс, тарифы, `lift_floor`) — обязательно.
- Колонка в Табеле зависит от **P3** (`computePayroll_`); вкладку «Финансы»
  можно релизить и без неё.
- Отложено: учёт оплат и реальная задолженность (реестр выставленных счетов
  со снапшотом суммы + статус «выставлен/оплачен»), выгрузка в Excel/PDF,
  свод «доходы минус зарплаты». Если понадобится долг — это отдельный тикет P5,
  колонка «Начислено» при этом остаётся как есть.

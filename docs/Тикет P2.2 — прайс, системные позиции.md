# P2.2. Прайс: фиксированные позиции доставки и подъёма, настраиваемый порог платной доставки

> Доработка P2. Форма позиции прайса сейчас позволяет создавать свои рейсы
> (trip: max_kg, oneway) и подъёмы (lift: per_floor) — лишняя свобода и риск
> рассинхрона с авторасчётом. Логистические позиции фиксируем, свободное
> создание остаётся только для стирки (по весу / поштучно).

## Принятые решения (контекст)

- **Фиксированный набор — 3 позиции:** «Доставка менее N кг», «Доставка в одну
  сторону/Забор», «Подъём на этаж».
- **Позиция «Доставка» (рейс без ограничения по весу) удаляется:** доставка
  партий от N кг и выше — бесплатна (подтверждено владельцем). Сейчас она —
  fallback для тяжёлых рейсов в `buildInvoice_`.
- **Порог N настраивается владельцем** — не только цена, но и граница веса,
  ниже которой доставка платная. Имя позиции в счёте генерируется из N:
  «Доставка менее 20 кг».
- **Визит в одну сторону** (только забор / только отвоз) тарифицируется
  позицией «Доставка в одну сторону/Забор» **независимо от веса** — как сейчас.
- У фиксированных позиций редактируются: стоимость (тарифы — дефолт прачки и
  переопределения клиентов, UI уже есть) и код НФ (ext_code, нужен для 1С);
  у пороговой — дополнительно сам порог N. Название, тип, параметры
  (oneway/per_floor), активность — зафиксированы, удаление запрещено.
- **`buildInvoice_` почти не трогаем:** при отсутствии подходящей позиции рейса
  `pickByTier_` возвращает `null` → строка в счёт не добавляется. Бесплатная
  тяжёлая доставка получается удалением позиции, ядро расчёта не меняется.

## Модель (BillingItems, новых таблиц нет)

| Позиция | kind | Параметры | Редактируется |
|---|---|---|---|
| Доставка менее N кг | trip | max_kg = N | **порог N**, цена, код НФ |
| Доставка в одну сторону/Забор | trip | oneway = да | цена, код НФ |
| Подъём на этаж | lift | per_floor = да (выше 2-го) | цена, код НФ |

- «Системность» определяется по `kind`: создание trip/lift закрыто, значит
  множество замкнуто без дополнительных флагов и колонок. Пороговая позиция —
  единственная trip с `max_kg` и `oneway ≠ да`.
- SCHEMA_VERSION → 6: только миграция удаления «Доставки» (см. ниже), новых
  колонок и таблиц нет.

## Сервер

### schema.js

- `START_BILLING_ITEMS` — 7 позиций (без «Доставка») для новых прачек.
- `migrateToV6_`: для каждой прачки удалить позицию `kind='trip'` без `max_kg`
  и без `oneway` (это ровно сидовская «Доставка») + её строки в `ClientTariffs`.
  Идемпотентно: страж миграции через `readAll_`, как в фиксе v4.
- Если в старой БД есть self-made trip/lift позиции (созданные до запрета) —
  не удаляем: они становятся замороженными «legacy» (см. правила ниже).

### saveBillingItem / deleteBillingItem (api.js)

- **Создание:** только `wash_weight` / `wash_pcs`; trip/lift → ошибка
  «Позиции доставки и подъёма фиксированы». Вторая активная `wash_weight` →
  ошибка (правило «одна весовая позиция на прачку» уже в схеме).
- **Правка пороговой позиции** (trip с max_kg): разрешены `max_kg`
  (целое > 0) и `ext_code`; `name` перезаписывается автоматически —
  «Доставка менее {N} кг». Остальные поля игнорируются/ошибка.
- **Правка oneway/lift:** только `ext_code`; попытка сменить название,
  параметры или `active` → ошибка.
- **Правка legacy trip/lift** (не из системного набора, если такие остались):
  только `active` (архивация).
- **Удаление:** только wash_*; trip/lift (системные и legacy) → ошибка.
- События в `Log` — как сейчас (`billingitem_*`), плюс детали смены порога.

### core.js

- Без изменений логики. Обновить комментарий к `pickByTier_`: «рейс без
  подходящей позиции строки не даёт — доставка от N кг бесплатна».

### Ретро-пересчёт (принято, предупредить в UI)

Счета и «Финансы» считаются на лету: после миграции (удаление «Доставки») и
при каждой смене N прошлые периоды пересчитаются по новым правилам. До
снапшотов выставленных счетов (P5) это осознанное поведение.

## UI (refs, вкладка «Прайс»)

- **Блок «Стирка»** — как раньше: создание/правка/удаление позиций стирки
  (название, код НФ, активна). В форме новой позиции: радио «по весу /
  поштучно» (вариант «по весу» недоступен, если активная весовая уже есть),
  единица выставляется по kind (кг/шт) — селект единицы убрать.
- **Блок «Доставка и подъём»** (фиксированный) — три строки:
  - «Доставка менее **N** кг»: инлайн-поле порога (число > 0) с подтверждением
    и подсказкой «прошлые периоды пересчитаются»; цена по умолчанию; код НФ.
  - «Доставка в одну сторону/Забор»: цена по умолчанию; код НФ.
  - «Подъём на этаж»: цена по умолчанию; код НФ.
  - Кнопок удаления, переключателя активности и параметров нет. Подсказка
    блока: «доставка от N кг — бесплатно; цены для конкретного клиента — в
    карточке клиента».
- **Поля max_kg/oneway/per_floor из формы уходят** — вместе с ними исчезают
  подписи «Ярус» и «Только одна нога»: патч подписей из P2.1 для этой формы
  отменяется за ненужностью (колонка «Ярус, кг» в таблице прайса, если ещё
  есть, тоже уходит).
- Карточка клиента (переопределения цен, привязки видов) — без изменений.

## Тесты (`node --test`)

- **Миграция v6:** «Доставка» и её тарифы удалены, остальные 7 позиций на
  месте; повторный запуск — без изменений; данные других прачек не тронуты.
- **Расчёт:** рейс ≥ N (оба плеча) — строк доставки в счёте нет; рейс < N —
  «Доставка менее N кг» × 2; pickup-only — oneway-позиция независимо от веса.
- **Смена порога 30 → 20:** партия 25 кг перестаёт тарифицироваться, 15 кг —
  тарифицируется; имя строки в счёте — «Доставка менее 20 кг».
- **Права/валидации:** create trip/lift → ошибка; переименование системной →
  ошибка; delete trip/lift → ошибка; вторая активная wash_weight → ошибка;
  порог 0/не число → ошибка.
- **Регрессия:** эталоны P2 (46560 / 51710 / 45800) не используют «Доставку»
  и проходят без изменений; в `finance.test.js` тест «объёмы клиента» и
  фикстуры, опирающиеся на позицию plain-тrip, поправить (рейс 100 кг больше
  не тарифицируется, `bi.trip` из хелпера убрать).

## Оценка

0,5–1 день: миграция + правила saveBillingItem (0,5 д), блоки прайса в UI
(0,5 д), правка тестов — заодно.

## Зависимости и отложено

- Поверх P2; с P3/P4 стыкуется само (зарплаты и «Финансы» логистику прайса
  не редактируют, расчёт общий через `buildInvoice_`).
- Отложено: несколько весовых порогов («менее 10 кг» дешевле, чем «менее
  30 кг») — если понадобится, отдельный тикет; платная тяжёлая доставка —
  если правило изменится, позиция возвращается тем же механизмом.

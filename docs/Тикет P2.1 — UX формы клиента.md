# P2.1. UX формы клиента (модалка в «Справочниках»)

> Дополнение к P2. Модалка клиента (`refs/client-form.tsx`) после P2 собрала
> семь секций подряд и три разные задачи. Цель: короткая модалка по умолчанию,
> предсказуемое сохранение, минимум шума. Сервер и API не меняются — только
> клиентская часть.

## Проблема (зафиксировано по коду формы)

1. **Длина и смешение задач.** В одном окне: карточка (5 полей), реквизиты,
   чеклист видов белья, учёт результата, эффективный прайс (строка на позицию
   прайса), привязка видов (строка на вид белья), счёт за период. При
   10 позициях прайса и 15 видах белья — 40+ строк.
2. **Разная семантика сохранения.** Основные поля — по кнопке «Сохранить»,
   цена — по `onBlur`, привязка — по `onChange`. «Отмена» не отменяет уже
   сохранённые цены/привязки — пользователь этого не знает.
3. **Шум по умолчанию.** У типичного клиента переопределены 1–2 цены и ноль
   нестандартных привязок, но видны все строки обеих секций. Маркеры
   «переопределено/наследовано/не задана» — серый текст, статус не считывается.

## Принятые решения

### 1. Аккордеон: короткая модалка по умолчанию

Свёрнуты по умолчанию: «Реквизиты», «Цены», «Привязка видов белья».
Развёрнуты: основные поля, «Виды белья», «Учёт результата» (нужны при
создании). В заголовке свёрнутой секции — сводка:

```
▸ Реквизиты (заполнены)  /  (не заполнены)
▸ Цены (2 переопределены · 1 без цены)
▸ Привязка видов (все по весу)  /  (3 настроены)
```

Состояние секций запоминается (ui store persist / localStorage): где раскрыл —
там и откроется в следующий раз. Компонент: маленький `ui/Accordion.tsx`
(заголовок-кнопка + сводка + контент), стили в `refs.module.css`.

### 2. Прайс: сначала важное

- Сортировка строк: переопределённые → с дефолтом → без цены.
- Видны сразу только **переопределённые** и **без цены**; остальные — под
  «Показать все позиции (8)».
- Маркеры — цветные бейджи: «переопределено» (синий), «наследовано» (серый),
  «не задана» (оранжевый). «Не задана» = дыра в счёте (`missing_prices`),
  должна бросаться в глаза.

### 3. Привязки: только нестандартные

Видны только виды с явной привязкой клиента; остальные — под спойлером
«Настроить по видам (12)» со сводкой «все по весу / как у типа».

### 4. Единое мгновенное сохранение (существующий клиент)

- Все поля сохраняются сразу: текст — по `onBlur`, селекты/чекбоксы/радио —
  по `onChange`. Как цены сейчас, но для всей формы.
- Футер для существующего клиента: «В архив» (danger, с подтверждением) +
  **«Закрыть»** вместо «Отмена»/«Сохранить» — закрытие ничего не откатывает,
  и это честно отражено в названии.
- У успешно сохранённого поля/строки — микроиндикатор «✓ Сохранено» рядом
  (не только общий тост в стороне).
- Валидация (ИНН 10/12 цифр, КПП 9) — на клиенте до отправки: при ошибке
  значение не уходит на сервер, поле подсвечено, подпись ошибки под полем.

### 5. Новый клиент — обычная форма

Режим создания не меняется: форма с кнопкой «Создать», zod-валидация как
сейчас, секций цен/привязок нет (нужен id). После создания модалка
закрывается; настройка цен — при повторном открытии.

### 6. «Счёт за период»: пилюли вместо голых дат

`[Этот месяц] [Прошлый] [Период]` + «Сформировать» — счёт почти всегда за
календарный месяц. **После P4 секция уезжает во вкладку «Финансы»** (строка
клиента → «Открыть счёт»), из модалки остаётся только ссылка «Открыть в
Финансах» — отдельным маленьким коммитом.

## Затронутые файлы

- `refs/client-form.tsx` — разбить: `ClientCardForm` (создание/карточка),
  `ClientPricesSection`, `ClientBindingsSection`, секции — в `Accordion`.
- `components/ui/Accordion.tsx` (+ css) — новый переиспользуемый компонент.
- `refs/refs.module.css` — бейджи, сводки, индикатор «✓ Сохранено».
- После P4: удалить `InvoiceSection` из модалки.

## Тесты (Playwright, `client/e2e/`)

- Создание: видны только поля карточки; ИНН 5 цифр → ошибка, не сохраняется;
  «Создать» → клиент в списке.
- Редактирование: секции свёрнуты, сводки корректны («2 переопределены»);
  раскрытие «Цены» → правка цены → «✓ Сохранено» без перезагрузки страницы.
- «Закрыть» после правки — значение не откатилось (переоткрыть и проверить).
- Прайс: строка с переопределением видна сразу; «Показать все» раскрывает
  остальные.
- Счёт: пилюля «Прошлый» формирует ссылку `/invoice?...from/to` прошлого
  месяца.

## Оценка

1 день: аккордеон + сводки (0,25), мгновенное сохранение всей формы (0,5),
фильтры прайса/привязок и бейджи (0,25), пилюли счёта + e2e (в объёме).
После P4 — перенос секции счёта в Финансы (+0,25 д).

## Зависимости

- Нет (сервер не трогаем). Перенос секции счёта — после **P4**.

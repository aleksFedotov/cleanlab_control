# Деплой CleanLab Control (Прачечная PRO) — чек-лист

Платформа: VPS, Node/Express + SQLite (`server/`). Выполняется вручную владельцем проекта. Порядок важен.

## 1. VPS и домен

1. VPS с Ubuntu LTS, публичный IP.
2. Домен (или DuckDNS-субдомен), A-запись на IP сервера — HTTPS обязателен для Telegram webhook.
3. Установить Node.js LTS и Caddy.
4. Caddyfile:
   ```
   cleanlab.example.com {
     reverse_proxy localhost:3100
   }
   ```
   Статику фронта раздаёт сам Express (`server/public/`), отдельная настройка не нужна.

## 2. Конфигурация — server/.env

```bash
cd server
npm install
cp .env.example .env   # заполнить
```

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `LAUNDRY_NAME` | имя первой прачки (сид при пустой БД) |
| `OWNER_PIN` | PIN владельца (глобально уникален, доступ ко всем прачкам) |
| `WORKER_PIN` | PIN первого сотрудника прачки 1 |
| `DRIVER_PIN` | PIN первого водителя прачки 1 |
| `LAUNDRY2_NAME` | имя второй прачки (необязательно; задаётся → создаётся сидом) |
| `LAUNDRY2_WORKER_PIN`, `LAUNDRY2_DRIVER_PIN` | пины первых пользователей прачки 2 |
| `WEBHOOK_SECRET` | случайная строка (напр. 32 символа) |
| `TV_KEY` | секретный ключ табло прачки 1 |
| `TV_KEY_2` | секретный ключ табло прачки 2 (если есть) |
| `PORT` | по умолчанию 3100 |
| `DB_PATH` | путь к SQLite-файлу (по умолчанию `server/data/cleanlab.sqlite`) |
| `APP_TZ` | по умолчанию `Europe/Moscow` |

`OWNER_CHAT_ID` не нужен — бот запишет его в Settings per-tenant на шаге 5.

Сид пользователей и прачек (`migrateToV2_`) срабатывает один раз, при пустой таблице `Laundries`. Дальнейшие пользователи заводятся владельцем через экран «Сотрудники», а не через ENV.

## 3. Запуск сервера

```bash
cd server
node --env-file=.env index.js
```

Слушает `localhost:3100`. БД и таблицы создаются сами. Для постоянной работы — systemd-сервис (или PM2) с автоперезапуском. Проверка: `curl localhost:3100/health` → `{"ok":true}`.

## 4. Инициализация данных

При первом старте создаются таблицы и сидятся прачки/пользователи из ENV. Стартовые типы белья и дефолтные Settings:

```bash
node --env-file=.env -e "require('./setup').setup()"
```

Идемпотентно, повторный запуск безопасен.

## 5. Telegram

1. Создать бота у @BotFather, токен → `BOT_TOKEN`.
2. Установить webhook прямо на VPS (Cloudflare-прокси из GAS-схемы больше не нужен):
   ```bash
   curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<домен>/telegram/webhook?secret=<WEBHOOK_SECRET>"
   ```
3. В Telegram написать боту `/start` → отправить `OWNER_PIN` обычным сообщением.
   - Прачка одна → ответ «дайджесты подключены ✓».
   - Прачек несколько → бот пришлёт список и попросит «`<PIN> <номер>`» (привязка чата per-tenant, повторить для каждой прачки при необходимости).

## 6. Fallback-дайджест

Если смена не закрыта, в `DIGEST_TIME` (Settings, по умолчанию 21:30) шлётся fallback-дайджест по каждой активной прачке. На VPS это cron/таймер, вызывающий `fallbackDigestTrigger` (см. `docs/vps-migration.md`).

## 7. Табло цеха

Ссылка: `https://<домен>/tv.html?key=<TV_KEY>` (прачка 2 — `TV_KEY_2`). Держать в секрете — это единственная защита табло. Ключ определяет, данные какой прачки показывать.

Железо (два варианта):
- **Вариант A — ТВ-приставка/Смарт-ТВ**: открыть ссылку в браузере ТВ, вывести на весь экран.
- **Вариант B — старый планшет/ноут на стене**: открыть ссылку, закрепить вкладку, отключить блокировку экрана.

Страница сама обновляется каждые ~45 сек, при потере связи показывает последние данные с красной плашкой.

## 8. Планшет сотрудника и водитель

Открыть `https://<домен>/`, выбрать прачку, войти персональным PIN, добавить на главный экран. Владелец заходит по `OWNER_PIN` (прачку выбирает на входе и переключает в шапке).

## 9. Проверка после деплоя

1. Владелец: Справочники → добавить клиента.
2. Неделя/Развоз: запланировать визит на завтра.
3. Сотрудник (вкладка «Цех»): «В работу» → вес → пересчёт → мешки → «Завершить».
4. «Закрыть смену» → владельцу в Telegram приходит дайджест.
5. Табло: счётчики и карточка стирки видны.
6. При двух прачках: переключение прачки у владельца меняет данные; табло каждой прачки показывает своё.

## Локальная разработка

```bash
cd server
npm install
cp .env.example .env
node --env-file=.env index.js   # localhost:3100
npm test                        # Node-тесты против SQLite in-memory
```

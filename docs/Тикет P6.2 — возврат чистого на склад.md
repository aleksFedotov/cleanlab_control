# P6.2. Водитель: поточечная кнопка «Вернуть чистое на склад»

> Продолжение серии P6 (правки визитов). Вся складская механика возврата уже
> существует (ветка `undo_take_clean` в `correctVisit`, P6) — тикет делает
> возврат штатным действием водителя, а не «исправлением ошибки».

## Проблема

Чистое, взятое водителем (`clean_taken_at`, маркер `consumed_at='driver'` на
складских записях), можно вернуть на склад только через модалку «Исправить» →
«Отменить "Взял чистое"» (`correctVisit` / `undo_take_clean`). Три изъяна:

1. **Возврат — не ошибка, а рабочая ситуация.** Клиент не принял / закрылся,
   план на завтра изменился после вечерней погрузки, точку переносят на другой
   день. Водитель не ищет штатную операцию в «исправлениях» — боится «сломать»
   данные и не нажимает.
2. **Аудит смешивает смыслы.** Возврат пишется в `Log` как `visit_correct`
   («исправление ошибки») вперемешку с реальными опечатками. Частые возвраты —
   полезный сигнал о качестве планирования развоза, сейчас его не выделить.
3. **Кнопка не там.** Потребность возникает в блоке «Мой груз» и на карточке
   точки, а операция живёт три клика глубоко в модалке правки. Итог: бельё
   «зависает» в грузе (`driverCargo_` показывает его вечно), точку неловко
   перепланировать.

## 1. Сервер (`server/deliveries.js`, регистрация в `server/api.js`)

### 1.1 Общий хелпер

Вынести тело ветки `undo_take_clean` из `correctVisit` в
`returnCleanForVisit_(v, laundryId)`:

- Storage: clean-записи клиента с `consumed_at='driver'` → `consumed_at=''`
  (снова на складе, экран «Склад» их видит);
- визит: `clean_taken_at=''`, `clean_bags=''`;
- возвращает число возвращённых мешков (значение `clean_bags` до очистки) —
  для тоста и `Log`.

`correctVisit('undo_take_clean')` перевести на этот хелпер — внешнее поведение
отката не меняется, событие `visit_correct` остаётся как было.

### 1.2 Новый метод `driverReturnClean(token, visitId)`

- Роли: `driver`/`owner` — `API_ROLES`: `driverReturnClean: DRIVER_OWNER`,
  регистрация рядом с `correctVisit` (делегирует в deliveries.js).
- Валидация: визит найден в тенанте; `clean_taken_at` заполнен (иначе
  `err_('Чистое по точке не взято')`); `delivered_at` пуст (иначе
  `err_('Чистое уже выдано — сначала отмените выдачу')`, как в undo_take_clean).
- Мутации — только через `returnCleanForVisit_`. **Статус визита не меняем**:
  `planned` остаётся `planned`, `picked` остаётся `picked` (возврат чистого
  на забранное грязное не влияет). Стирки не трогаем (`done`/`stored` как были,
  `WashItems` не затрагиваются).
- `Log`: отдельное событие `clean_return`, details `{ client_id, date, bags }`.
- Ответ: `ok({ visit, cargo: driverCargo_(laundryId), returnedBags })`.
- Идемпотентность: повторный вызов после успешного возврата падает валидацией
  «не взято» — склад не дублируется (записи уже без маркера `driver`).

## 2. UI (`client/src/app/driver/page.tsx`)

- **Карточка точки:** там, где сейчас метастрока «🚚 чистое у вас: N меш.»
  (условие `v.clean_taken_at && !v.delivered_at`, см. `visitMeta`), добавить в
  список действий кнопку «↩ Вернуть чистое на склад (N меш.)». Тон —
  secondary/warn, не основная: это не ход сценария «выдал/забрал».
- **Подтверждение** (`ui/ConfirmDialog`): «Вернуть на склад N меш.? Точка
  останется в маршруте, чистое снова появится на складе». Без подтверждения
  нельзя — работа в перчатках, случайный тап не должен разворачивать погрузку.
- **Во время запроса** кнопка блокируется, спиннер с текстом (spec §7.1);
  ошибка — красная плашка, состояние экрана не теряется.
- **После успеха:** тост «Возвращено N меш.», инвалидация query-ключа маршрута;
  карточка перерисовывается: метастрока становится «✨ чистое на складе…»,
  действие «Взял чистое» снова доступно. Блок «Мой груз» пересчитывается сам
  (cargo в ответе).
- Точка со статусом `picked` (грязное забрано): кнопка тоже доступна.

### Не входит в тикет

- **Частичный возврат** (2 мешка из 5): складские записи — партии стирок,
  поштучно мешки не трекаются. Нужен — отдельный тикет, операция через склад.
- **Массовая кнопка «Сдать всё чистое на склад»** (аналог `driverHandover`):
  опасна для завтрашнего груза. Если понадобится — отдельный тикет с диалогом
  выбора точек, а не «всё разом».

## 3. Тесты (`server/test/`, `node --test`)

- Возврат: clean-записи `consumed_at='driver'` → `''` (открыты);
  `clean_taken_at`/`clean_bags` очищены; статус визита не изменился
  (`planned` → `planned`, `picked` → `picked`).
- Запреты: без взятия → «не взято»; после выдачи (`delivered`/`both`) →
  ошибка, склад не меняется.
- Стирки не тронуты: `done`/`stored`, `issued_at` пуст, `WashItems` на месте.
- `Log`: событие `clean_return` с `bags`; отсутствует `visit_correct`.
- `cargo` после возврата: `clean_points`/`clean_bags` уменьшились на точку.
- Права: `worker` → «Нет доступа»; визит чужой прачки → «не найден».
- Повторный возврат → ошибка, склад не дублируется (открытых записей столько
  же, сколько было до взятия).
- Регрессия: `correctVisit('undo_take_clean')` через хелпер — старое поведение
  сохранено, событие `visit_correct`.
